How to tag MT5 trades by economic calendar events

To tag a MetaTrader 5 trade with economic events, read the built-in calendar with CalendarValueHistory for the symbol's currency, keep the high-importance events, convert both the event times and the trade time to UTC, and keep the events within a window (for example 15 minutes) of the entry or the exit. Match events by their event_code, not by their name.

Why the time conversion matters

The calendar returns event times in the broker's server time, shifted by the server's offset at the moment you read it, not the offset that was valid on the day of the event. Many brokers run on New York time + 7 hours: GMT+2 in winter and GMT+3 while the US is on daylight saving time. Read a summer event in winter and it comes out one hour early. Convert the event with today's offset, and the trade with the offset of its own date.

MQL5 code

// US daylight saving: 2nd Sunday of March 07:00 UTC to 1st Sunday of November 06:00 UTC.
datetime NthSunday(const int year, const int month, const int n)
  {
   MqlDateTime t;
   ZeroMemory(t);
   t.year = year; t.mon = month; t.day = 1;
   datetime first = StructToTime(t);
   TimeToStruct(first, t);
   return first + ((7 - t.day_of_week) % 7 + 7 * (n - 1)) * 86400;
  }
bool UsDst(const datetime utc)
  {
   MqlDateTime t;
   TimeToStruct(utc, t);
   return utc >= NthSunday(t.year, 3, 2) + 7 * 3600 && utc < NthSunday(t.year, 11, 1) + 6 * 3600;
  }
// Server time to UTC for a broker on New York time + 7 hours.
datetime ServerToUtc(const datetime server)
  {
   datetime summer = server - 3 * 3600;
   return UsDst(summer) ? summer : server - 2 * 3600;
  }
// The server's offset now, rounded to 30 minutes.
int ServerOffsetNow()
  {
   return (int)(MathRound((double)(TimeTradeServer() - TimeGMT()) / 1800.0) * 1800);
  }
// Print the high-importance events of a currency within window_min minutes of a trade moment.
void EventsNear(const datetime trade_server_time, const string currency, const int window_min)
  {
   datetime trade_utc = ServerToUtc(trade_server_time);
   int      now_off   = ServerOffsetNow();
   MqlCalendarValue v[];
   if(CalendarValueHistory(v, trade_utc + now_off - 86400, trade_utc + now_off + 86400, NULL, currency) < 0)
     {
      Print("Calendar not available, error ", GetLastError());
      return;
     }
   for(int i = 0; i < ArraySize(v); i++)
     {
      MqlCalendarEvent ev;
      if(!CalendarEventById(v[i].event_id, ev) || ev.importance != CALENDAR_IMPORTANCE_HIGH) continue;
      datetime ev_utc = v[i].time - now_off;           // calendar time uses today's offset
      if(MathAbs((double)(ev_utc - trade_utc)) <= window_min * 60)
         PrintFormat("%s %s at %s UTC", currency, ev.event_code, TimeToString(ev_utc));
     }
  }

Call it for the entry and for the exit, and for each currency of the symbol. Gold, US indices and Bitcoin react to US events, so use USD for them; a currency pair uses both its currencies.

Pitfalls

  • Names are translated. MqlCalendarEvent.name comes in the terminal's language. event_code does not: for example nonfarm-payrolls, consumer-price-index-mm and fed-interest-rate-decision.
  • Several releases in one minute. CPI month on month, year on year and core CPI come out together. Count them as one event, or every CPI trade is counted three times.
  • Just after start. For a few seconds after the terminal starts, TimeTradeServer() can return GMT, which gives an offset of 0. Check the offset against your broker's model before using it.
  • No calendar. On some networks the terminal cannot reach the calendar service and CalendarValueHistory fails (we saw error 5401). One failed request can block for about 50 seconds, so do not retry it for every trade. In the Strategy Tester the calendar functions are not available (error 4014).
  • Other brokers. If your broker's server time follows other rules, replace ServerToUtc with its model.
